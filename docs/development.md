## 预编译发布包

Release 提供完整固件、独立标题字库、免编译刷机工具和校验清单。下载版安装见 [刷机说明](FLASHING.md)。发布包不包含个人 NVS、聊天缓存、串口日志或全 Flash 备份；默认固件和字库分别写入 `0x0`、`0x510000`。

0.11.1 的发布校验要求工厂镜像中存在唯一、以 NUL 终止的完整固件版本，并与清单精确相等。`0.11.0-rc.1` 或 `0.11.01` 不会被接受为 `0.11.0`；混合版本也会被拒绝。独立刷机包的 `--check` 继续只依赖 Python 标准库。

源码工具 `tools/flash.py` 在任何写入前使用 `esptool --chip esp32p4 --no-stub read-mac` 核验选中芯片并读取基础 MAC，应用进入 ROM 后的 MAC 必须对应先前的 `TAB5-…` 应用序列号。重启后的端口名可以变化，但必须由同一芯片的应用序列号返回准确匹配的 `STATUS` 固件版本，才报告验证成功。其他已连接的 Tab5 不能满足重连检查。ROM 端口需显式选择，S3 不可通过 P4 检查；全过程沿用共享串口锁，状态验证不输出聊天元数据。

## 中英界面

`UiLocale` 在控制台、设置和游戏中选择中英文文本。完整 factory 刷入后默认英文；设置页可切换，偏好延迟持久化并在普通重启后保留。factory 镜像包含跨越 NVS 的填充，再次刷入会重置主题、音量、亮度和语言；跳过字库不保留 NVS。语言变化触发界面重绘，不翻译聊天标题，也不改变原生 Micro 事件枚举或 STATUS 的机器可读字段。布局使用现有反锯齿字体与可见字形度量；英文标签按可用宽度选用合适字号。

## 构建和 USB 适配

工具链、首次安装步骤和字体烧录见 README。`platformio.ini` 使用独立 `.pio-core/`，`prepare_platform.py` 获取固定 SHA 的项目本地平台并校验补丁。`prepare_core.py` 仅用于复制已有匹配缓存，不是新安装的必要步骤。

Tab5 的 USB-C 使用 ESP32-P4 full-speed PHY0（GPIO24/25）。`tools/usb_fs_patch.py` 编译项目本地 Arduino USB 文件和 TinyUSB 0.21.0 HID 类，使用 64 字节 HID OUT 缓冲，避免 SDK high-speed 缓冲配置影响 full-speed 主机请求。补丁校验 SDK 版本、源锚点和供应商文件校验和，不修改全局框架。

CDC 在 USB 身份确定后显式启动，接收缓冲为 8192 字节。主循环每次最多解析 256 字节，避免较长元数据行挤占触摸处理。同步、截图和刷机共享串口锁；诊断工具只选择应用 VID/PID 和有效的 Tab5 应用序列号，不回退到任意 Espressif ROM 设备。

`partitions.csv` 面向 16MB Flash，包含 5MB factory 应用分区。动态标题字体独立放在 `0x510000`。首次安装或修改分区时刷入 factory 镜像；普通应用更新可以保留字体。

## 0.12.0 蓝牙实现与验证边界

P4 运行 UI 与原生协议，板载 C6 通过 ESP-Hosted／SDIO 提供 BLE 控制器。无线初始化在独立 worker 中进行，失败时保留 USB。C6 可用、广播可见和 MTU 协商完成都不表示已配对；还需完成 PIN、绑定、加密与认证。首次使用应先解锁 macOS，在系统蓝牙设置中完成配对，再让 companion 继续同步。

BLE 暴露 HID 服务 `0x1812`，使用厂商 usage page `0xFF00`、原生 report ID 6 和 63 字节 report payload；Device Information 的 PnP ID 对应 `0x303A:0x8360`。相同 VID/PID 只是识别条件之一，不能独立证明桌面动作已执行。USB 和 BLE 的接收组包、发送队列及会话号分别维护，避免拼接或跨连接重放。

输入只发往一个选中的连接，USB 挂载优先。切换前给旧连接有限时间发送释放／归中，必要时断开无法清理的旧蓝牙会话；剩余手势不会在新连接上继续。正常接回 USB 保留 BLE 绑定及连接。设备上的 **USB／BLE submitted** 仅表示传输栈接受，不是桌面执行回执。

配对采用显示六位随机 PIN、加密、MITM 认证与绑定。新身份只能在用户开启的 120 秒窗口内完成配对；已绑定身份可自动重连。认证完成时再次核对窗口和连接会话，过期握手不能获得新绑定；替换既有绑定也需要配对窗口。连接页提供蓝牙开关、开始配对和带确认的清除绑定。

固定 SDK 的 ECC 兼容修复仅将 `uECC_shared_secret` 路由到 SDK 的 mbedTLS ECDH 接口，保留 TinyCrypt 密钥生成及 Secure Connections。构建前核对 SDK 身份与 `libbt.a` SHA-256，变化时停止构建；P4 启动自测使用 RFC 5903 P-256 已知答案。NimBLE 连接处理保留早于 `CONNECT` 到达的 `ENC_CHANGE` 与 CCCD 状态；本地 `BLEService` 补丁避免按 UUID 去重丢失 HID Report，保留五个 Report 特征及只读 `0x2908` 描述符，并用标准 Service Changed 通知已绑定主机更新 GATT。

### 独立元数据 GATT

以下 UUID 共享尾部 `-7d4b-4b58-9e53-5e4ad07e7a50`：

| UUID 前段 | 用途 |
| --- | --- |
| `8f4d1000` | 元数据服务 |
| `8f4d1001` | RX，带应答写入，认证加密后接收行片段 |
| `8f4d1002` | TX，认证加密后通知，可按 MTU 拆分应答 |
| `8f4d1003` | Identity，认证加密读取 |

Identity 为 `{"v":1,"serial":"TAB5-0123456789AB","maxLine":6144,"firmware":"tab5-micro-0.12.0"}`；串号为示例，实际必须对应 **P4 USB 芯片身份**。`firmware` 仅供诊断，桥接不要求其字符串排它匹配。广播厂商数据 `0x303A` 后的六字节 P4 MAC 只用于候选筛选，连接后仍需检查 Identity 协议字段及公开串号。

本项目真实固件强制 Identity、RX、TX 使用加密且经过 MITM 认证的链路，首次绑定要求系统 PIN 配对。主机端公开串号匹配没有提供应用层密码学设备认证，不能阻止复制 UUID／广播串号并明文回应 GATT 的主动仿冒外设骗取元数据；该威胁当前未处理。实机加密与配对结果适用于本固件，不是 companion 已排除克隆的证据。详见 [设备身份边界](BLUETOOTH.md#设备身份边界)。

RX 仅允许 `TITLES <json>\n` 与 `HOST_CONFIG <json>\n`，不接受按键、截图、刷机等诊断命令。桌面按 ATT MTU 分片，设备按换行组包，成功应答为 `TITLES_OK <seq>`／`HOST_CONFIG_OK <seq>`。`0x18` 单字节无应答地清空未完成行，避免写入超时后补一个换行意外执行旧状态。消息与应答绑定当前 BLE 会话，断线后不迁移旧数据。

只有 `title_sync.py` 连接设备；`chat_state_bridge.py` 继续只写缓存。前者持有独立跨进程 BLE owner 锁并保留 GATT 连接，避免第二个进程抢连或关闭原生 HID 共用的连接。auto 优先同一串号的 USB，USB 锁忙时跳过，正常 USB 接回不主动断开 GATT。重新连接后及每个数据包发送前重读源数据，不缓存待重放的聊天快照。

macOS 使用 Bleak 3.0.1 与 CoreBluetooth。扫描合并公开 API `retrieveConnectedPeripheralsWithServices` 返回的外设，覆盖系统 HID 已连接、外设停止广播的情况。BLEDevice 的 `(peripheral, manager)` 适配依赖固定版本后端，升级 Bleak 时需复核该契约。未知身份只接受唯一候选，禁止按名称、RSSI 或 C6 MAC 猜选。建立链路的预算为 15 秒；读取加密 Identity 的预算单独为 60 秒，认证等待不占用 USB 串口锁。这不会延长 SMP 事务约 30 秒的超时；macOS 的 PIN 提示可能来自独立 BluetoothUIServer 对话框，应解锁电脑并及时输入。

相关合成测试覆盖身份校验、MTU 分片、通知组包、写入中断、重连不重放、USB 优先、owner 锁、缓存刷新和 PIN 窗口策略。合成测试不替代实机证据；已确认的配对、Fast／Plan 桌面执行、元数据与自动回退，以及仍待验收的项目，分别记录在下方 0.12.0 验证摘要中。

## 输入契约

| 触摸 | 原生事件 |
| --- | --- |
| 外环顺／逆时针 | 每圈 24 步，`ENC_CW`／`ENC_CC`，`act:2` |
| 旋钮中心 | `ENC`，按下 `act:1`、释放 `act:0` |
| 摇杆拖动 | `v.oai.rad`，归一化角度和距离；释放后发送归中 |
| Agent／Command 键 | 成对的按下／释放事件 |

手势从首次接触捕获到释放，穿过别的键不会触发它们。旋钮穿过中心后重新锚定角度，避免跳动；没有松手后的惯性输入。原生旋钮模式、长按、麦克风和自定义动作由桌面应用处理，固件不将它们替换为通用键盘快捷键。

0.11.1 将原生输入与协议应答放入有界队列，每次轮询尝试提交一个 HID 分片；端点忙或提交失败时保留位置，不在触摸路径等待 USB 完成。多分片应答保持连续，摇杆仅合并同方向区间内尚未提交的移动，不跨越阈值、方向或归中事件合并。

同一 USB 会话内，排队输入过期、队列满或诊断暂停会取消未提交的动作。已经提交的按下与摇杆位移则优先补发释放／归中，恢复完成前不接受新的按下。真正 USB 卸载会清空队列、会话和恢复状态：重连不会重放旧按下、旋转、释放或半条应答。释放事件本身也可能触发桌面动作，因此不能跨会话重放。

按钮的“USB未发送”表示提交失败或队列拒绝，不表示事件仍在等待发送，也不承诺之后会发送。只有完整消息成功交给 USB 栈后才显示“USB已提交”；提交成功不证明桌面收到了消息或执行了映射。

`INPUT_TEST` 使用同一触摸路径和事件序列化器，但将产生的事件送回 CDC，抑制电脑端 HID 操作。60 秒无测试输入自动退出；结束后要求现有手指先抬起再恢复电脑控制。测试捕获不等于桌面应用执行验证。

## 元数据边界

原生 Micro 的灯光消息保留六个 Agent 槽位以及 `keys`、`ambient` 区域的颜色、亮度、效果、速度和 magic 字段。状态文字由标准配色推断，自定义配色可能改变含义。

标题 companion 只解析明确的本地 Custom assignments，再按 ID 读取所需标题；不从最近访问时间猜测槽位。收到的标题最多 191 个 UTF-8 字节，截断只发生在完整字符边界。`TITLES` 和 `HOST_CONFIG` 使用独立应答，同一批次共享 uint32 序号；任一应答失败不会阻止另一种元数据尝试发送，失败批次可重试。

`HOST_CONFIG` 的可选 `joystick_up` 仅允许 `unknown`／`plan`。只有完整有效的桌面 v1 布局中 Up 实际映射到 `composer.togglePlanMode` 才传 `plan`；布局省略 `analogStick` 时按已核对的桌面默认映射展开。自定义或无效映射、不可用的配置源，以及未携带此字段的旧包均为 `unknown`。该字段只是已读取的配置事实，不证明实时执行目标或动作已经执行，也不传输任何自定义命令文本。

普通 watch 每秒检查一次数据变化，约两秒发送心跳。每种消息有独立 1.5 秒应答预算；读超时时保留部分应答行。设备在 7.5 秒没有有效更新、活动连接失效或切换时将元数据标记过期。

连接证据分层处理：`usb_mounted` 是当前 USB 挂载；`native_session_seen` 是当前选中传输会话曾收到原生主机消息，不是持续存活检测；标题、配置和聊天设置各自有新鲜度。页眉区分 USB／BLE 连接和“最近”灯光，不能用最后的 RGB 值证明实时桌面状态。连接失效或切换会清理相应会话与元数据。

### 指定聊天的真实设置

`chat_state_bridge.py` 连接已有桌面 Unix 协调 socket，注册本地数据客户端，订阅明确聊天的连续 revision。它不启动 app server、不恢复聊天、不发送消息，也不发现桌面当前选中的聊天。

接受的下一轮设置用于确定 Fast／Standard、Plan／Default 和权限预设。缺失值保持 Unknown；明确 `serviceTier:null` 或 `default` 表示 Standard。Full access 需要匹配完整权限预设，不能仅凭 `approvalPolicy:never` 推断。自定义配置保持 Custom，不向缓存保留工作区路径或自定义配置名。

桥接只保留所需的设置投影，不写入对话正文、工具输出或原始 IPC 帧。缓存权限为 0600，原子更新；断开连接、owner 丢失或 revision 缺口会使状态无效。companion 拒绝超过六秒的状态缓存。桌面 IPC 为内部版本化接口，应用升级不兼容时应明确显示未知。

权限增量 patch 如果涉及无法用当前投影安全重建的未知审批字段或结构，会立即使投影失效并请求完整快照。自定义审批的简化标记也不能拿来增量重建原对象；重新同步前显示未知，不能继续显示旧的 Full access 等预设。快照仍只保留经过筛选的设置，不把新增字段的原始值、路径或配置名写入缓存。

0.11.1 用独立只读“指定聊天设置 / Tracked settings”条显示桥接值，旁边明确标示“操作目标未核对 / Target not verified”。Fast／Plan／Approve 原生按钮保留桌面映射，不再用跟踪聊天的设置标亮或改名。跟踪聊天标题也不证明 HID 命令指向该聊天；桌面当前选中目标和桥接目标仍相互独立。

## 字体与两行滚动

固定标签和动态标题均来自固定版本的 Noto Sans SC Medium。静态字体包含原生 16／20／24／26／28／32／40px 反锯齿子集；动态标题单独使用 24px BMP 字体，覆盖 30,445 字形。不支持的字符逐个替换，不因一个缺字将整行退回旧字体。

标题资产格式 `T5VLW4` 保留 VLW 度量表，位图存储为 4-bit alpha。内存映射读取器将其按需展开为 M5GFX 可读取的数据，不逐字形分配堆内存。加载前验证头、尺寸、长度和 CRC。生成器输出固定上游 SHA、资产 SHA、字形数、尺寸和 Pillow 版本清单。

```sh
.venv/bin/python tools/build_ui_font.py --check
.venv/bin/python tools/build_title_font.py
.venv/bin/python tools/build_title_font.py --check
```

每个标题窗高 50px，使用两行 25px 行距。英文优先保持完整单词，中文允许按字符边界换行，并尽量避免标点出现在不合适的行首／行尾。短标题居中，最多两行时保持静止，不增加省略号。

超过两行后，先停留 2.2 秒，再用一秒上移一行；末尾附加前两行使循环连贯。任何触摸都会暂停时钟，松手后保留一秒阅读停顿再继续。打开设置或游戏时暂停，返回后不根据消逝的墙钟时间跳过内容。

内容、字体或宽度改变时才重新光栅化文字并缓存 alpha 条带。滚动时恢复干净背景再合成，不重新绘字或分配内存。主题／按压背景变化时重新捕获背景，保持滚动位置。标题与霓虹边框共用空闲更新预算，每帧最多刷新一个空闲区域，输入相关重绘优先。

`TITLE_SCROLL_TEST` 仅在 `INPUT_TEST` 中有效，用于可重复的虚拟绝对时钟验证；退出捕获自动清除。正常生产滚动使用真实时钟。`FX FREEZE` 将普通标题固定在头两行，便于像素比较。

## 材质、霓虹与局部更新

大面积背景、面板和按键面使用确定的 RGB565 纯色，阴影集中在边缘，避免全屏颗粒纹理。圆角、旋钮边缘、刻度和图标采用亚像素覆盖；少量渐变使用固定蓝噪声阈值，完整与局部重绘使用相同坐标保证一致。

活动霓虹位于键帽边缘，文字区域不参与动画。边框更新和标题更新不会重复绘制整张卡片；按压及主题切换会使相关背景缓存失效并重新捕获。

0.11.1 在较长的材质绘制、标题光栅化和像素写回之间加入 `RenderService` 检查点，协作采样触摸、处理有界 USB 接收并推进发送队列。渲染使用一份状态快照；检查点不重入绘制、不写偏好、不切换方向，也不分派会重入渲染的 CDC 命令。它缩短绘制期间的输入服务间隔，不意味着完整重绘已变成瞬间完成，完整帧耗时仍单独记录。

游戏生命周期在页面可见性改变时立即处理离开与暂停，不依赖下一次绘制是否观察到中间页面。快速切到控制台再返回仍保持暂停，只有显式继续才恢复模拟；隐藏游戏不推进本局。

触摸区域在视觉键帽外适当扩展，键间空隙保留独立手势边界。这是基于屏幕尺寸和目标大小的设计审查，尚无正式用户研究或可用性认证。

## 声音与方向

音频走板载 Codec 的 I2S/PCM 路径。短音按旋钮、按键和摇杆事件节流，设置页调整音量时提供预览；音量、静音和亮度在释放触摸后延迟保存，避免拖动过程中频繁写入 Flash。

P4 SDK 的默认 USB 调试 PHY 管脚处理与音频 GPIO26/27 有冲突，因此必须保留 `micro_sound.cpp` 中释放调试 PHY 的处理，并在 USB 启动前初始化音频。不要在运行中任意重建 Speaker 或 USB 驱动。

方向策略使用加速度的重力投影和陀螺仪稳定性，在两个横屏方向间切换。螺丝孔朝下对应 rotation 3，反向对应 rotation 1；触摸、截图或诊断捕获期间不改变坐标系。平放、竖向、剧烈移动和传感器异常时保持当前方向。

这些触摸回归工具使用诊断捕获，阻止合成触摸事件触发电脑操作。清理代码会退出捕获、清除预览并恢复设置；方向验证可能需要手动摆放设备。

`verify_transition_performance.py` 单独测量白天／黑夜、中英语言、设置打开／关闭、游戏库／控制台切换，以及六个槽位和指定聊天的新标题缓存构建。每阶段先清除性能统计，仅发送短命令并静置，再读第一份 `STATUS`，要求同步绘制已返回；它分别记录命令 ACK 时间、完整绘制和输入服务间隔，不把 ACK 当成画面完成。

该工具拥有隔离的 `INPUT_TEST` 捕获，只使用合成预览，不写真实标题或 `HOST_CONFIG`，不传输 `SCREEN`，不发送原生电脑操作，并在结束时恢复页面与设置。输出仅保留性能和本地状态白名单。默认只采集基线；可用 `--max-input-us` 指定此次检查的输入服务间隔阈值。“首次标题”指新的排版／光栅缓存，字体存储本身可能已经预热。这些统计不证明真实手指到像素的延迟，也不证明桌面执行了原生动作。

`verify_screenshot_stream.py` 检查截图二进制流跨越 60 秒捕获 watchdog 时是否完整。它在冻结的合成预览和隔离按下状态下取得参考帧，再通过仅限捕获模式的 `SCREEN_TEST_SLOW` 让设备按 **28,000 B/s** 发送；主机始终连续读取，避免依赖主机串口缓存行为来制造设备背压。工具校验帧头、精确像素字节数、结束标记、与参考帧一致的内容，以及帧后延迟输出的释放事件和 `STATUS` 清理结果。

`verify_host_feedback.py` 和 `verify_title_font.py` 的状态／标题是隔离的合成演示。`verify_chat_bridge.py` 会实际调整明确测试聊天的下一轮模式并恢复原值；运行前阅读 `--help`，使用专门的测试聊天。它验证状态回传，不能单独证明原生 HID 操作已经执行。

`verify_ble_native.py` 默认只做本地预检，不打开 USB／BLE。显式 `--execute` 会检查映射、解锁状态、指定聊天缓存及操作者对活动目标的确认，再安排有限的原生事件并暂时断开 USB 数据接口。报告分别记录排队完成、同一 BLE 会话的发送增量、macOS 仅有 Bluetooth 设备的拓扑，以及指定聊天的真实状态变化与恢复；它不通过设置 IPC 制造预期变化。`transport_verified` 与 `desktop_execution_confirmed` 必须分别解读。旋钮的导航高亮执行以桌面该分支才生成的原生 ambient 反馈及配对采集的实机帧为证据，不能推断具体 DOM 焦点或控件身份。

Fast／Plan 已使用严格时序检查再次通过：完整执行区间保持 BLE-only 且无异常，同一会话各准确提交四条预期原生消息；桌面变化必须来自 ARM 之后实际读取的目标缓存，并观察到中间状态与恢复，不能使用安排输入之前的缓存变化作为成功证据。

旋钮灯效诊断由 USB 预先安排基线、顺转后、逆转后和恢复四帧，在 USB 数据接口断开后的同一认证 BLE 会话内保存帧缓冲及对应渲染状态，之后再取回。测试关闭预览与冻结，并对照 Agent 槽位状态，避免把模拟灯效、输入提交提示或后台运行色误认成桌面导航回传。每帧分成 113 段、每段不超过 16KiB 复制，持续服务输入并核对会话及 UI 状态；最终实机复测通过。

常用 CDC 命令：

| 命令 | 作用 |
| --- | --- |
| `STATUS` | 固件、输入、字体、元数据和绘制统计；可能含聊天标题／ID |
| `SCREEN` | 将当前帧缓冲复制到 PSRAM 并分块导出 RGB565 |
| `SCREEN_TEST_SLOW` | 仅限 `INPUT_TEST` 捕获模式，以 28,000 B/s 发送测试截图；普通模式拒绝 |
| `THEME LIGHT`／`THEME DARK` | 本地主题切换 |
| `LANGUAGE EN`／`LANGUAGE ZH` | 切换英文／中文界面 |
| `PLAY`／`MICRO` | 游戏库／控制台切换 |
| `PERF_RESET` | 清除性能统计 |
| `PERF_FULL`／`PERF_DIRTY` | 完整呈现基线／普通局部呈现 |
| `BOOTLOADER`／`RESTART` | 进入 ROM 下载模式／重启 |

截图传输期间 companion 暂时无法取得串口锁，所以传输后的元数据可能超过 TTL；这不改变 SCREEN 时已经复制的画面。需要验证实时状态时，应同时保存截图之前的新鲜 STATUS，传输后释放锁并等待 companion 更新。

- 长标题滚动差异局限在标题窗内；长标题替换为短标题以及按键／摇杆操作后，局部恢复与完整重建的像素比较无残影。
- 七个长标题窗完成缓存与场景稳定后，在无 STATUS 轮询的四秒样本中记录 66 次标题更新，最大绘制 2.433ms，最大输入采样间隔 5.004ms。
- 音效同时工作时，旋钮样本最大绘制／输入间隔为 14.820／19.002ms，摇杆为 21.628／25.002ms。

这些是短时设备端样本，不是普遍性能上限，也不是电脑端操作延迟。全屏切换、初次字体准备和诊断传输应与稳定的交互样本分别测量；持续轮询 STATUS 本身会影响 USB 和主循环时序。
